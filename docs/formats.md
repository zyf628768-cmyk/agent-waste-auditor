# Formats and compatibility

Canonical format version is `1.0`. Check `schemas/event.schema.json`, `dataset.schema.json`, `audit.schema.json` and `comparison.schema.json`; no network schema resolution is required. Runtime validation enforces financial constraints (including read+write ≤ inclusive input), while schemas describe serialized interchange. Schema generation lives in `scripts/generate_schemas.py`.

## Generic events

One JSON object per UTF-8 JSONL line, or CSV with the same field headers. UTF-8 BOM and Windows/Linux newlines are supported. CSV numbers are parsed as integers/decimal strings; booleans must be lowercase `true`/`false`. Empty CSV cells are unavailable. Unknown fields are dropped; `arguments` is a special import-only field used to produce a SHA-256 signature after redaction and is then discarded. File paths inside arguments need not exist and are never opened. Use forward or escaped backslashes as required by JSON; the CLI accepts native platform paths including Unicode/spaces.

Required: `schema_version`, `id`, `task_id`, `agent`, timezone-bearing ISO `timestamp`, `kind` (`model`, `tool`, `human`, `wait`, `task`). IDs must be unique after privacy normalization. Optional `status`: success/failed/timeout/unknown/running. Omitted status is unknown. A failed **task** marker is distinct from a failed tool/model step. An explicit subsequent task marker clears the post-failure detector's state.

Optional cost fields: `amount` (nonnegative finite decimal string), `currency` (three uppercase letters), `origin` (actual/estimated/manual); all three are required together when charging. `category` can be model/tool/failure/rework/wait/quality. Default derives from event kind. Explicit amounts override model price estimation, and are assumed to represent the entire event charge; split separate charges into separate events. A zero explicitly priced tool is different from an unpriced tool. No automatic duplicate dollar detection across different events/invoices is possible; reconcile input scope yourself.

Model fields: exact `model`, nonnegative integer `input_tokens`, `output_tokens`, `cached_tokens`, optional `cache_write_tokens` (default zero). Canonical input includes both cache reads and writes. `cached_tokens` must be known, including explicit zero, before estimates are allowed. Do not include reasoning tokens again if they are already in provider output totals. Audio/image-specific units, tiered pricing and provider tool charges need explicit amounts or pre-normalized separate events.

Evidence fields: `action` (short tool label), `signature` and `context_signature` (stable digest or import-time label to hash), `progress` (explicit true/false), `retry_reason` (unknown/transient/user_requested/idempotent_check). No progress evidence is different from false progress. `duration_ms`, `queue_ms`, `human_wait_ms` are nonnegative integer counts; unknown durations remain absent. `synthetic` labels fixture data. `source_line` is assigned by import, not a path; IDs plus line number map evidence back to the explicitly selected source file. Different sources should be imported separately to retain this mapping.

## Task metadata

`--tasks` takes a JSON array. `task_id` is required/unique. Optional `agent`, `task_key`, `difficulty`, `acceptance_id`, `status` (success/failed/running/unknown), `accepted` boolean, `baseline_minutes`, `human_minutes`, `rework_minutes`, `hourly_rate`, `currency`, `baseline_verified` boolean and `synthetic` boolean. Human minutes exclude rework. `hourly_rate` requires currency. A task without events cannot establish observed cost coverage. `model`, `prompt_strategy`, `workflow` label experiment dimensions; if model is omitted, a single observed model may be inferred. Use distinct task IDs for independent attempts and the same task key/acceptance ID for equivalent work. Task metadata should reflect actual completion and acceptance, not model optimism.

## Pricing

JSON object with `schema_version: "1.0"`, `prices` array. Every price requires unique `id`, exact `model`, `currency`, `source`, inclusive ISO date windows `effective_from`/`effective_to`, `input_per_million`/`output_per_million`. Read/write rates are separate optional `cache_read_per_million`/`cache_write_per_million` and required when those usages are nonzero. No overlapping windows for one model. Price date selection uses the event's recorded timezone/calendar date; normalize source timestamps if provider billing uses a different business date. No automatic price download, expiry extension or matching of model aliases. Distinct cache TTL/tier configurations require distinct explicit model labels/rates.

## Codex native: `codex-rollout-structural-v1` (experimental)

Explicit file with `session_meta.payload.id` and optional `cli_version` with major 0. Missing version emits VERSION_UNAVAILABLE; other major versions are rejected. This identifies the version and checks structure, **not a guarantee that every 0.x minor release is compatible**. Require observed `turn_context.payload.model` for estimation; otherwise model is unknown. Parse `event_msg.payload.type=token_count` and `info.total_token_usage` deltas (input/output/cached_input/cache_write_input). Repeated unchanged snapshots are ignored. Backward counters are rejected rather than guessed around resets. Missing cumulative totals are warned/omitted, never reconstructed from repeated `last_token_usage` snapshots.

`response_item` function_call entries retain name + argument digest; matching function_call_output text is discarded. Exit status cannot be reliably inferred from arbitrary prose, so tools remain unknown status/unpriced absent canonical enrichment. Messages/instructions are ignored. Multiple sessions in one file are unsupported. If a log omits token events, cost coverage is unavailable. Subscriptions are not priced as if API estimates were actual charges. Reference for native semantics: [official Codex implementation](https://github.com/openai/codex/blob/main/codex-rs/core/src/session/mod.rs). No access to actual private user transcripts was used during development.

## Claude Code native: `claude-assistant-structural-v1` (experimental)

`type=assistant`, `sessionId`, `timestamp`, optional `version` with major 2, `message.id`, `message.model`, `message.usage` and content tool_use blocks. Other major versions rejected; missing versions warned; minor-version compatibility is structural, not guaranteed. Last observed usage for a message ID wins, avoiding repeated assistant-block charges; contradictory session/model identity must be reviewed. Cache read/creation counts are added to the provider's uncached input. One write rate only: no inferred cache TTL or split-rate pricing. Tool_use ID deduplicates tool entries and payload is hashed; tool-result statuses and native human task acceptance are not inferred. Assistant text, thinking and user messages are discarded. Only synthetic local fixtures were validated; [official Anthropic cache guidance](https://github.com/anthropics/skills/blob/main/skills/claude-api/shared/prompt-caching.md) documents cache usage fields, not a stable public local-transcript contract.

## OpenAI objects: `openai-completed-objects-v1`

One non-streaming completed Responses (`object=response`) or Chat Completions (`object=chat.completion`) JSON object per line. `id`, Unix integer `created_at`/`created`, `model`, `usage` (input/output or prompt/completion) and cached token details. `task_id` is an optional import envelope extension; absent it, each response is its own task. Response IDs must be unique. Missing cached-token details mean incomplete usage, not zero. Streaming chunks, aggregate organization usage/cost endpoints, request-response wrappers, Batch result envelopes, Assistants traces and realtime/audio events are not supported. This adapter consumes supplied records only and does not call OpenAI or require credentials.

## Failure behavior

Invalid JSON, unsupported generic versions, malformed required fields, negative/nonfinite money, impossible caches, duplicate event IDs and native major-version incompatibility are rejected with exit 2 by the CLI. Errors intentionally do not echo source contents/paths. Doctor returns exit 1 for failed read-only checks. Empty generic input imports as empty with warning; doctor marks it unavailable. No silently invented fields. Unrecognized native non-cost message types may be ignored, with experimental-profile/outcome warnings; absence of parsed events is explicit.
